# Результаты перехода на PaddleOCR с GPU-ускорением

Мы перевели распознавание текста на изображениях с устаревшего Tesseract OCR на современный нейросетевой PaddleOCR с использованием GPU-ускорения (NVIDIA CUDA) и изоляцией в отдельном Docker-контейнере.

## Что было сделано

1. **Создан микросервис `ocr-service`**:
   - `Dockerfile.ocr` базируется на официальном образе `ccr-2vdh3abv-pub.cnc.bj.baidubce.com/paddlepaddle/paddle:3.0.0-gpu-cuda12.6-cudnn9.5-trt10.5` с CUDA 12.6 и cuDNN 9.5.
   - Устранена ошибка сборки (`Cannot uninstall PyYAML`): в `Dockerfile.ocr` добавлен шаг предварительной переустановки пакета с флагом `--ignore-installed PyYAML`.
   - Внедрен `ocr_service.py` на базе FastAPI, который инициализирует PaddleOCR на GPU при старте и предоставляет endpoint `POST /ocr` для распознавания текста.

2. **Адаптация под API PaddleOCR v3.0.0**:
   В процессе запуска мы столкнулись с изменениями в API новой мажорной версии PaddleOCR 3.0.0 и успешно адаптировали код:
   - Аргумент `use_gpu` удален — теперь используется `device="gpu"` (или `device="cpu"` для фоллбэка).
   - Аргумент `use_angle_cls` переименован в `use_textline_orientation=True`.
   - Метод `ocr()` помечен как устаревший — теперь используется `predict()`.
   - Изменился формат вывода: вместо списков координат и кортежей v2.x метод `predict()` возвращает структурированный словарь, где распознанный текст лежит в ключе `rec_texts`.

3. **Интеграция бота с микросервисом**:
   - `src/services/ocr.py` полностью очищен от локального Tesseract и методов предобработки. Теперь он отправляет асинхронные HTTP-запросы (через `aiohttp`) в контейнер `ocr-service`.
   - В `src/bot/handlers.py` вызов `image_to_text` теперь нативно асинхронный (вызовы через `loop.run_in_executor` удалены).

4. **Оптимизация докер-окружения и кэширование**:
   - Из `Dockerfile` бота удалены системные зависимости Tesseract OCR, что сделало образ бота очень легким. Из `pyproject.toml` удалена библиотека `pytesseract`.
   - В `docker-compose.yml` добавлен сервис `ocr-service` с лимитами ОЗУ (`4G`), CPU (`2.0`), пробросом GPU (`deploy.resources.reservations`) и размером `shm_size: '8gb'`.
   - **Оптимизация кэширования**: Добавлено монтирование тома `./paddlex_cache:/root/.paddlex` для сохранения скачанных нейросетевых моделей на хосте. При перезапуске контейнера модели не скачиваются повторно, и инициализация происходит мгновенно.

## Исправление: Поддержка ценников формата "400-00" без знака валюты

При распознавании ценников в российских магазинах часто встречается формат записи вида `400-00` или `250-99` (рубли и копейки через дефис) без явного указания символа валюты (`₽`, `руб.`). В строгом режиме (который используется для фото) бот игнорировал такие числа для исключения ложных срабатываний.

Мы добавили интеллектуальную поддержку этого формата:
1. В `src/services/recognizer.py` добавлен шаг предобработки текста: регулярное выражение находит паттерн `(?<![\d-])\b(\d+)-(\d{2})\b(?![\d-])` (рубли-копейки) и преобразует его в формат `\1.\2 ₽`.
2. Шаблон защищен от ложного срабатывания на телефонные номера и дефисные диапазоны (например, `123-45-67` или `100-200`) с помощью негативных просмотров назад и вперед `(?<![\d-])` и `(?![\d-])`.
3. Поскольку символ `₽` является строгим, основной парсер успешно распознает цену как `RUB` даже в строгом режиме.
4. Добавлены соответствующие тесты в `tests/test_recognizer.py`, которые подтверждают корректность логики.

## Исправление: Поддержка вертикального (разнесенного по строкам) формата ценников и OCR-опечаток

На некоторых ценниках рубли, копейки и валюта («руб.») находятся на разных вертикальных уровнях, из-за чего PaddleOCR распознает их на разных строках (например, отдельно `299`, на следующей строке `95` и далее `py6.`). Кроме того, из-за особенностей шрифта OCR часто распознает «руб» как латинские «py6», «pyб» или «pyb».

Для решения этой проблемы:
1. **Объединение строк (stacked layout)**: В начале метода `parse` мы добавили алгоритм, который объединяет строки, если идет последовательность: `[число рублей]`, `[1-2 цифры копеек]`, `[валютный токен]`. Они объединяются и приводятся к каноническому формату со строгим символом (например, `299.95 ₽`). 
2. **Алгоритм защищен** от ложного склеивания обычных строк с помощью проверки длины (короткие строки `2\n$` не склеиваются) и валидации валютных токенов.
3. **Обработка OCR-ошибок**: В словарь slang-слов `SLANG_MAP` добавлены варианты опечаток OCR для рублей: `"py6"`, `"pyб"`, `"pуб"`, `"pyb"`.
4. **Успешно протестировано**: Локальный тест на базе реального вывода распознавания со второго ценника пользователя показал 100% верный результат (`299.95 RUB`). Все 99 тестов успешно пройдены, контейнеры пересобраны и запущены.
